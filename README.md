# Исход — рынок прогнозов для собственного VPS

Код находится **в корне этого проекта**. Для запуска не нужны Sites, ChatGPT, Cloudflare или внешняя база. Node.js 24, встроенный SQLite, HTML/CSS/JS. Зависимостей npm нет.

- `server/` — HTTP-сервер, email/пароль, сессии, SQLite, администратор и резервное копирование.
- `lib/api.mjs` — сделки, позиции, баланс, история и погашение рынков.
- `lib/market-math.mjs` — математика LMSR.
- `public/` — интерфейс и личный кабинет.
- `migrations/` — схема базы, применяется автоматически при запуске.
- `tests/` — математические, транзакционные и HTTP-тесты.
- `compose.yml`, `Dockerfile`, `deploy/nginx.conf` — запуск на сервере.
- `legacy/sites/` — прежняя реализация для Sites, сохранена для справки. В контейнер и архив для VPS не включается.

## Быстрый запуск в Docker

Из корня проекта:

```bash
cp .env.example .env
# В .env проверь APP_ORIGIN: адрес сайта без завершающего слеша.
# По умолчанию в примере: https://project1.anatolii-botov.ru

docker compose up -d --build
docker compose ps
curl -f http://127.0.0.1:3101/healthz
```

Контейнер слушает `3000`, на VPS опубликован **только** `127.0.0.1:3101`. SQLite хранится в Docker-томе `ru-polymarket_ishod-data`, а не внутри слоя контейнера. Пересборка и `docker compose down` сохраняют данные; `docker compose down -v` удаляет том и базу.

Для проверки только на своём компьютере без Nginx:

```bash
APP_ORIGIN=http://localhost:3101 docker compose up -d --build
```

Открыть `http://localhost:3101`. Можно зарегистрировать несколько пользователей с разными email и проверить общий рынок. Пароль — от 10 до 128 символов. Новый пользователь получает 10 000 виртуальных баллов один раз.

`APP_ORIGIN` должен совпадать с адресом в браузере: он используется для проверки запросов и выбора HTTPS-cookie. HTTPS автоматически добавляет `Secure` к session cookie.

## Администратор

Обычная регистрация всегда создаёт пользователя без прав администратора. Прав администратора не даёт даже регистрация с email владельца.

Создай администратора из терминала сервера:

```bash
docker compose exec app node server/admin.mjs
```

Команда запросит email и новый пароль, ввод пароля скрыт. Если аккаунт уже существует, его баланс/позиции сохранятся, пароль обновится, роль станет административной, прежние сессии завершатся. Если аккаунта нет, он будет создан. Затем войди через обычную форму сайта.

В личном кабинете администратора доступно завершение тестового рынка с выбором «Да»/«Нет». Победителям автоматически начисляется по 100 Б за долю; повторные выплаты исключены.

## Заливка на VPS

Готовый архив: `outputs/ru-polymarket-deploy.tar.gz`. Он включает рабочий код, Docker, тесты и Nginx; исключает `.env`, локальные базы, Git, `node_modules` и прежний Sites.

С компьютера:

```bash
scp outputs/ru-polymarket-deploy.tar.gz USER@VPS_IP:~/
```

На VPS с установленными Docker Engine и Compose:

```bash
mkdir -p ~/ru-polymarket
tar -xzf ~/ru-polymarket-deploy.tar.gz -C ~/ru-polymarket
cd ~/ru-polymarket
cp .env.example .env
nano .env

docker compose up -d --build
docker compose exec app node server/admin.mjs
curl -f http://127.0.0.1:3101/healthz
```

DNS A-запись `project1.anatolii-botov.ru` должна указывать на IP VPS. Если выбран другой домен, замени его и в `.env`, и в `deploy/nginx.conf`.

## Nginx и HTTPS

Конфигурация уже готова в `deploy/nginx.conf`:

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/project1
sudo ln -s /etc/nginx/sites-available/project1 /etc/nginx/sites-enabled/project1
sudo nginx -t
sudo systemctl reload nginx

sudo certbot --nginx -d project1.anatolii-botov.ru --redirect

curl -I https://project1.anatolii-botov.ru
sudo certbot renew --dry-run
```

Если symlink уже существует, повторно создавать его не нужно. Настраивай вход и регистрацию через HTTPS после Certbot. Заголовки `Host`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto` передаются Nginx. График обновляется HTTP-запросами, WebSocket не нужен. `TRUST_PROXY=true` в Compose используется для ограничения попыток входа по адресу, переданному собственным Nginx.

Приложение не затрагивает другие сервисы на портах 3000/3102 и других поддоменах: наружу у него опубликован только loopback-порт 3101.

## Обновление и проверка

После замены исходников на VPS:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
curl -f http://127.0.0.1:3101/healthz
```

Тесты выполняются при сборке Docker-образа. Если тест не проходит, сборка останавливается. Миграции базы применяются при старте приложения; уже применённые миграции не повторяются. Запускай **один экземпляр app** с этим SQLite-томом.

## Резервная копия

Согласованный снимок работающей базы, включая пользователей, пароли, сессии и сделки:

```bash
docker compose exec app node server/backup.mjs /data/backups/ishod.sqlite
mkdir -p backups
docker compose cp app:/data/backups/ishod.sqlite ./backups/ishod.sqlite
```

Для следующего снимка используй новое имя. SQLite backup API сохраняет согласованную копию даже при включённом WAL; простое копирование только основного файла работающей базы для этого не подходит. Храни резервные копии приватно.

Для восстановления останови app, сохрани копию текущего тома, замени базу согласованным снимком и убери старые файлы `ishod.sqlite-wal` и `ishod.sqlite-shm` перед стартом. Восстановление откатывает все данные к моменту снимка.

## Без Docker

Node.js >=24.0:

```bash
APP_ORIGIN=http://localhost:3000 npm start
```

Открыть `http://localhost:3000`. По умолчанию SQLite создаётся в `data/ishod.sqlite`. Для администратора: `node server/admin.mjs`. Запуск тестов: `npm test`. Установка npm-зависимостей и сборка frontend не требуются.

## Что работает

Регистрация по email и паролю, вход/выход, смена пароля, профиль, серверный баланс, покупка и продажа, портфель, журнал операций, график по реальным сделкам, сохранённое событие и погашение рынка. Пароли хешируются scrypt с отдельной солью. Сессии в HttpOnly/SameSite-cookie; в базе хранится хеш токена. Ограничение попыток входа сохраняется в SQLite. Клиент не может выбрать другого пользователя, назначить роль или изменить баланс.

Смена пароля завершает все сессии аккаунта. Подтверждение email и восстановление пароля через почту пока не реализованы; отправки писем нет.

## Математика и целостность

LMSR с `b=100` долей. Доля победившего исхода погашается по 100 Б. Начальные цены 50%/50%; каждая покупка и продажа изменяет общую цену. Текущая цена и история исполнений связаны с общими позициями рынка. Для заполнения длинных периодов отдельно хранится сценарная предыстория.

`C(q) = 100 × b × ln(exp(q_yes/b) + exp(q_no/b))` в баллах.

Покупка стоит `C(q+Δ)−C(q)`, продажа возвращает `C(q)−C(q−Δ)`. Цена «Да» — `exp(q_yes/b)/(exp(q_yes/b)+exp(q_no/b))`. Расчёт учитывает размер заявки и проскальзывание. Реализация использует устойчивый log-sum-exp.

Деньги хранятся целым числом сотых балла, доли — целым числом тысячных. Покупка округляется вверх, продажа вниз до 0,01 Б: циклы покупки/продажи не создают баллы. Одна заявка ограничена 10 000 долями. Резерв маркетмейкера стартует с 6 931,48 Б, пополняется покупками и расходуется на продажи/погашение.

Сделка выполняется атомарной SQLite-транзакцией: проверяются версии рынка/кошелька, средства и доли; затем изменяются баланс, позиция, резерв и история. Устаревшая котировка возвращает 409 и требует нового подтверждения. Уникальный идентификатор заявки исключает повторное списание. Погашение защищено от повторной выплаты и гонки с покупкой.

Источник модели: [Robin Hanson, Logarithmic Market Scoring Rules](https://hanson.gmu.edu/mktscore.pdf).

В кабинете показываются последние 200 операций, в графике — до 223 точек выбранного периода: начало и закрытия временных интервалов. Полная история остаётся в базе. MVP использует виртуальные баллы, 12 событий и ручной выбор итога администратором; платежей и вывода денег нет.

## Открытый каталог и графики

Главная страница показывает 12 событий с категориями, поиском и сортировкой. Прямой адрес события: `/#market/metro-spb-2026` (либо другой ID из `lib/catalog.mjs`). Личный кабинет — `/#account`.

Каталог, правила, источники, котировки покупки и графики доступны без регистрации. Вход открывается в модальном окне по кнопке пользователя, при покупке или переходе в кабинет. Форма не является частью прокручиваемой страницы. Запись сделок, продажа личных долей, избранное, профиль и администрирование требуют сессии.

Публичные API: `GET /api/markets`, `GET /api/markets/:id`, `GET /api/history?marketId=:id&period=all`, `GET /api/quote?marketId=:id&side=yes&amountCents=100000`. Они не возвращают профили, балансы, позиции или журнал чужих сделок.

Новый рынок начинает с 50/50. Изменения текущей цены проводятся сделками пользователей и сценарного маркетмейкера, если он включён. Каталог дополняется при запуске без сброса существующих цен, позиций и истории. Определения вопросов находятся в `lib/catalog.mjs`; это условия будущих исходов, а не заявления об уже состоявшихся событиях.

Шрифт — Inter Variable с кириллицей, размещён локально в `public/fonts/`. Лицензия находится рядом в `OFL.txt`; запросов к сервису веб-шрифтов для отображения интерфейса не требуется.

## Сценарное движение котировок

`SIMULATION_ENABLED=true` включает автономный сценарий; в Compose он включён по умолчанию. Для отключения новых сценарных сделок установи `SIMULATION_ENABLED=false` в `.env` и пересоздай app: `docker compose up -d`. Уже записанная история при этом сохраняется.

Каждый рынок обновляется по собственному устойчивому расписанию: интервал примерно 4–11 секунд и отдельное смещение по времени. Планировщик проверяет сроки раз в 200 мс, SSE передаёт изменения с такой же частотой. Сценарий задаёт целевую вероятность: нерегулярные многодневные тренды, периоды низкой активности и редкие импульсы с постепенным затуханием. Детерминированный шум разных масштабов заменяет повторяющиеся синусоиды. Цели ограничены 12–88%. Цена не перезаписывается напрямую: внутренний маркетмейкер покупает доли или продаёт только собственные доли через тот же атомарный механизм LMSR. Размер одной части перемещения ограничен 0,4 доли. Балансы, резерв и погашение продолжают сходиться по проводкам. Если другой пользователь успел изменить цену, устаревший шаг пропускается.

У каждого рынка отдельный служебный кошелёк с однократным начислением 1 000 000 Б. У него нет пароля или сессии, и управлять им через публичные API нельзя. Сценарий не меняет деньги и доли обычных пользователей. Для завершённых и истёкших событий движение останавливается.

При первом включении создаётся **модельная предыстория за 90 дней**, строго до первой существующей точки рынка, в отдельной таблице `scenario_history`. Это сгенерированные значения, а не исторические пользовательские сделки. Публичный API явно отмечает такие точки `source: "scenario"`; реальные сценарные сделки отмечены `source: "simulation"`, обычные данные рынка — `source: "market"`. В таблице `trades` сценарные сделки имеют `source: "simulation"`, пользовательские — `source: "user"`.

При старте или восстановлении выполняется не более 60 пропущенных сценарных шагов на рынок после последней существующей сделки. Повторный запуск не дублирует выполненные шаги и не начисляет кошелькам средства повторно. Существующие пользовательские сделки, позиции и цены не сбрасываются.

Периоды графика: 5м, 1ч, 6ч, 1д, 1н, 1м, 3м и «Всё». Выборка покрывает целиком нужный интервал, а не последние N записей. При большом числе тиков сохраняются первая, последняя, минимальная и максимальная цены каждого временного блока, плюс цена перед началом окна. Это сохраняет длинные тренды и краткие пики. Шкала в браузере использует границы интервала из API.

### Живые котировки и лента

Публичный `/api/stream` передаёт Server-Sent Events `quotes` при изменении рынков; `/api/live` даёт такой же снимок для резервного опроса. В ответах только котировки и последние сделки без имён, email, идентификаторов пользователей и кошельков. Главная обновляет числа и мини-графики без замены карточек; стрелки показывают последнее изменение в процентных пунктах. Лента содержит фактические записи внутренних покупок/продаж, включая сценарные сделки с `source: "simulation"`; внешние новости не имитируются.

В `deploy/nginx.conf` для `/api/stream` отключены buffering/cache и увеличен таймаут. При обновлении VPS замените эту конфигурацию и выполните `sudo nginx -t && sudo systemctl reload nginx`. Без SSE сохраняется резервный опрос раз в 5 секунд.

Миграция модели v2 пересоздаёт только сгенерированную предысторию и привязывает будущую траекторию к текущей котировке. Пользовательские сделки, фактическая история, деньги и позиции сохраняются. Основной график использует закрытия временных интервалов; плавная кривая проходит через выбранные значения без выхода за локальные границы. Мини-графики визуально сокращают выборку, не меняя котировки и торговые расчёты.
