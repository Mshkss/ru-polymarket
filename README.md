# Исход — рабочий MVP рынка прогнозов

Один тестовый рынок. Общие для пользователей цены, реальные серверные сделки и график из истории этих сделок. Виртуальные баллы, без платежей.

## Возможности

- Вход через ChatGPT; первый вход создаёт аккаунт с 10 000 Б. Идентификатор задаёт платформа, клиент не может выбрать другого пользователя.
- Личный кабинет: имя, email, позиции, доступный баланс, сделки и журнал начислений/списаний. Всё хранится в Cloudflare D1 и доступно с другого устройства.
- Покупка и продажа долей «Да» / «Нет». Предварительная серверная котировка показывает среднюю цену, итоговую сумму, цену после сделки и выплату при выигрыше.
- График содержит начальную точку 50% и точки исполненных сделок. Другие пользователи видят изменения при обновлении раз в 5 секунд. Никаких случайных цен и нарисованной истории.
- Администратор завершает тестовый рынок с исходом «Да» или «Нет». Победившие доли погашаются по 100 Б, проигравшие — по 0. Начисление выполняется однократно в общей транзакции.

## Запуск

Node >=22.13, `npm ci`. `.openai/hosting.json` содержит идентификатор существующего Site и D1 binding `DB`.

1. `npm run build`
2. Применить по порядку SQL из `drizzle/` к локальной D1 (каждый файл один раз):
   `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_light_chronomancer.sql`
   затем аналогично `drizzle/0001_tough_wong.sql`.
3. Для локального администратора создать игнорируемый `.dev.vars`: `ADMIN_EMAIL=seedy@sites.test`.
4. `npm run dev -- --hostname 127.0.0.1 --port 5173`.
5. Открыть `/market.html`; локальный вход через `/signin-with-chatgpt?return_to=/market.html` создаёт только локальную тестовую личность Seedy. Подмена входа не включается в production.

На опубликованном Site вход принадлежит Sites. Аудитория Site остаётся закрытой; для тестирования с другими людьми владелец должен предоставить им доступ в Sites. Приложение поддерживает отдельные аккаунты и общий рынок. Локальный и опубликованный D1 — разные базы.

`ADMIN_EMAIL` хранится в runtime secrets Sites; владелец назначен администратором. Никаких секретов в исходниках. `.dev.vars` и база `.wrangler/` игнорируются Git.

## Математика

Это автоматизированный маркетмейкер LMSR, а не стакан заявок. Параметр ликвидности `b=100` долей. `q_yes`, `q_no` — суммарное количество непогашенных долей; в базе они хранятся в тысячных доли.

`C(q) = 100 × b × ln(exp(q_yes / b) + exp(q_no / b))` в баллах.

`P(Да) = exp(q_yes / b) / (exp(q_yes / b) + exp(q_no / b))`, `P(Нет) = 1 − P(Да)`.

Покупка `Δ` долей стоит `C(q+Δ)−C(q)`, продажа возвращает `C(q)−C(q−Δ)`. Это учитывает проскальзывание; текущую цену нельзя умножать на весь объём заявки. Покупка на бюджет подбирает максимальное количество тысячных доли бинарным поиском. Расчёты используют устойчивый log-sum-exp.

Балансы и проводки хранятся целым числом сотых балла. При покупке стоимость округляется вверх до 0,01 Б, при продаже выплата округляется вниз; циклы покупки/продажи не создают баллы из округления. Ограничение заявки — 10 000 долей.

Начальный резерв маркетмейкера `ceil(100 × b × ln 2 × 100) = 693148` сотых балла (6 931,48 Б), покрывающий максимальный убыток LMSR. Покупки пополняют резерв, продажи и погашения уменьшают его. Начальные пользовательские баллы — отдельные тестовые начисления.

Источник модели: [Robin Hanson, Logarithmic Market Scoring Rules](https://hanson.gmu.edu/mktscore.pdf).

## Целостность данных

Каждая сделка — атомарный D1 batch: проверка версий рынка и кошелька, наличия средств/долей, изменение кошелька, позиции, резерва, цены, проводка и точка истории. Неуспешная проверка откатывает весь batch. Пользователь не может уходить в минус, продавать чужие доли или торговать закрытым рынком.

Заявка содержит версию котировки и денежный лимит. Устаревшая цена возвращает 409 и требует повторного подтверждения. Идентификатор заявки предотвращает повторные списания при двойном клике или сетевом повторе. Незавершённый запрос сохраняется только для безопасного повтора; баланс и позиции всегда берутся с сервера.

Погашение защищено статусом и версией рынка, журнал выплаты уникален для пользователя и рынка. Это исключает двойную выплату и конфликт погашения с покупкой.

## Проверки

`node --test tests/math.test.mjs tests/api.test.mjs`

Математические свойства и интеграционные проверки с настоящим локальным D1/Miniflare: два пользователя, начальное начисление один раз, изменение общей цены, история, владение долями, продажа, недостаток средств, конкурентные заявки, повторы, CSRF, изоляция профилей, погашение и гонка сделки с погашением. Проверяется равенство кошелька сумме его проводок, суммарных позиций — эмиссии долей, резерва — денежным потокам.

## Границы MVP

Один заранее заданный рынок, ручное определение исхода администратором, вход через ChatGPT. Нет платежей, вывода денег, стакана, коротких позиций, внешнего оракула и редактора рынков. Список операций в кабинете ограничен последними 200, график — последними 2 000 точками выбранного периода; полные записи остаются в базе. Новые прогнозы добавляются отдельной задачей.
